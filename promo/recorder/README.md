# ナレーション録音 (promo/recorder)

デモ動画のナレーションを、自分の声で 1 文ずつ録るためのブラウザのページです。原稿を大きく出し、録り、声をくっきりさせるフィルターを聞きながら合わせ、読み上げソフトの声と同じ名前・同じ形の WAV (`N00_1.wav` など、44.1 kHz・16 bit・モノラル) で作業フォルダに保存します。保存するたびに `voice.json` も書き直すので、そのまま `subs.py layout`・`bgm.py mix` に使えます。

外のライブラリは使いません (ブラウザは Web Audio API・AudioWorklet・OfflineAudioContext だけ、サーバーは Python の標準ライブラリだけ)。ファイルは `index.html`・`recorder.css`・`recorder.js` (画面)・`dsp.js` (フィルター・大きさの計算・WAV)・`serve.py` (手元のサーバー)。

## 使い方 (1 つ起動 → 録る → 自動で保存)

```
py promo/recorder/serve.py --work 作業フォルダ
```

作業フォルダに、この 1 行を書いた .bat を置いておけば、ダブルクリックで始められます。

1. **起動する。** サーバーが 127.0.0.1 (この PC の中だけ) の空いたポート (既定 8790、使われていれば 8791, 8792 …) で立ち、既定のブラウザでページが開きます。同じ作業フォルダのサーバーがもう動いていれば、新しく立てずにページだけ開きます。
2. **原稿と合成の声は、ひとりでに出ます。** 画面の上の 1 行に、いまの状態が出ます:

   ```
   原稿 narration.tsv (36 文) | 合成の声 36 本 (voice/aida_calm) | 保存先 voice/recorded (12/36 文 保存済み)
   ```

3. **「マイクを使う」を押し、ブラウザの許可を出す。** http://127.0.0.1 のページなので、マイクが使えます。「入力」で機器を選べます (選んだものは覚えます)。
4. **録る。** スペースで録り始め、もう一度スペースで止めます。→ で次の文へ。
5. **保存はひとりでに。** 「選んだ録音を自動で保存」(既定で on) のあいだは、録った 1 本 (★) をフィルターに通して `作業フォルダ/voice/recorded/N00_1.wav` に書き、`voice.json` を書き直します。☆ で別の 1 本を選び直しても、その 1 本で書き直します。保存した文は左の一覧に「保存 ✓」、まだの文は「未保存」と出ます。
6. **止める。** サーバーの窓で Ctrl+C (または窓を閉じる)。録音はブラウザの中にも残るので、次に起動すると続きから録れます。

フィルターのつまみを変えたあとは、「選んだ録音を全部保存」で全部の文を今のフィルターで書き直してください (自動の保存は、録ったときと ★ を選んだときだけ走ります)。

### serve.py の引数

| 引数 | 既定 | |
|---|---|---|
| `--work` | (要る) | 作業フォルダ |
| `--script` | `作業フォルダ/script/narration.tsv` | 原稿 |
| `--synth` | `作業フォルダ/voice/aida_calm/` | 合成の声 (読むだけ) |
| `--out` | `作業フォルダ/voice/recorded/` | 録った声の保存先 |
| `--port` | 8790 | ここから空いたポートを探す (20 個まで) |
| `--no-browser` | | ページを開かない |

サーバーがすること (`serve.py` の先頭にも書いてあります):

- `GET /api/status`: 原稿の名前と文の数、合成の声のファイル、保存先にそろっている文。
- `GET /api/script`: 原稿の中身。毎回ファイルから読むので、原稿を直したらページを開き直せば新しい原稿になります。
- `GET /api/synth/<名前>`: 合成の声の `voice.json` と `<カット>_<番号>.wav`。
- `PUT /api/take/<カット>_<番号>.wav`: 録った声 (16 bit の WAV) を保存先に書き、`voice.py adopt` と同じ処理 (`adopt` をそのまま呼ぶ) で `voice.json` を書き直して、そろった文と足りない文の数を返す。名前は原稿の文の名前 (`N00_1.wav` …) だけを受け付けます。`../` や `\` を含む名前、原稿に無い名前、WAV でない中身は 400 で断ります。
- 127.0.0.1 だけで待ち、`Host` が 127.0.0.1・localhost でない要求と、ほかのサイトの `Origin` からの PUT は断ります。ページのファイルは `promo/recorder/` の直下の .html・.css・.js だけを出します。

### サーバー無しで開く (前からの形)

`index.html` をそのままブラウザで開くこともできます。このときは:

- 「原稿を読む (TSV)」で原稿を選ぶか、ページに TSV をドラッグする。「合成の声のフォルダ」で合成の声の WAV のフォルダを選ぶ (この 2 つの釦はサーバー無しのときだけ出ます)。
- 書き出しは「この文を書き出す」「選んだ録音を全部書き出す」(ダウンロード、0.25 秒ずつ空ける)、「フォルダを選んで保存」(File System Access API。Chrome・Edge だけ)。
- そのあと `voice.py adopt` を手で打つ (下の「動画に使う」)。
- file:// ではマイクが使えないブラウザがあります。そのときは `serve.py` で開いてください。

## 原稿の形

- 形は `promo/voice.py` の原稿と同じです: `#` の行は注、ほかは 1 行 1 文で、タブで区切った 4 列 (カット・枠 `m:ss-m:ss`・日本語・英語)。同じカットの文は同じ枠を持ちます。
- 左の一覧にカットごとに文が並びます。カットの行には、枠の長さと「声に使える」長さ (枠 − 頭の 0.3 秒 − 尾の 0.2 秒 − 文と文の間 0.35 秒 × (文の数 − 1))。頭と間の値は `subs.py` の `LEAD_S`・`GAP_S` と同じ、尾の 0.2 秒は原稿の注 (slots re-cut … tail 0.2 s) に合わせています。
- 文ごとの「目安」は、カットの「声に使える」長さを文に分けたものです。合成の声があれば合成の声の長さの比で、無ければ文字数の比で分けます。合成の声がある文は「▶ 合成の声」で聞き比べられます。
- いまの文の位置はブラウザに覚えます。

## 録る

真ん中に、いま録る文を大きく (日本語)、その下に英語を小さく、上と下に前後の文を薄く出します。

| キー | すること |
|---|---|
| スペース | 録る / 止める (合図の途中なら取りやめ) |
| → | 次の文 |
| ← | 前の文 |
| R | この文を録り直す (前の録音は残る) |

- 「3・2・1 の合図」に印があると、録り始める前に右上に 3・2・1 が出ます (文は隠しません)。
- 録っている間は、枠が朱の線で囲まれ「● 録音中」が点滅します。帯が 2 本出ます:
  - 「この文」: 経過の秒と、この文の目安の残り。目安の 9 割で黄、超えると朱。
  - 「カット」: このカットのほかの文 (録ってあれば選んだ 1 本の長さ、無ければ目安) とこの文の経過を足したものと、カットの「声に使える」長さ。
- 上のメーターは入力の大きさ (フィルターの前) です。赤い線はピーク (1.5 秒保つ)。0 dBFS 近くに達すると「クリップ」が 2 秒出ます。出たら、マイクのつまみか声を下げて録り直します。
- 文ごとに何回でも録れます。録音の一覧の ☆ を押した 1 本が、その文で使う 1 本 (★) です。最初の 1 本は自動で ★ になります。長さは頭と尾の無音を詰めた目安です。✕ で捨てられます (保存先のファイルは消しません)。
- 録音はブラウザの中 (IndexedDB) に残るので、ページを開き直しても消えません。ブラウザのサイトのデータを消すと消えます。サーバーのポートが変わると (8790 が使われていて 8791 で開いたときなど) ブラウザの中の録音は別の場所になり、見えなくなります。保存先の WAV はそのまま残ります。

マイクのエコー消し・ノイズ消し・自動の音量合わせはブラウザの側で切っています (素の声を録り、手を入れるのはこのページのフィルターだけにするため)。録音はマイクの信号をそのまま (圧縮しない PCM で) 取り込みます。

## 声のフィルター

録音は素の声のまま残し、フィルターは聞くときと保存するときにかけます。録ったあとでつまみを変えても、録り直す必要はありません。

ノードの並び (`dsp.js` の `buildChain`):

```
入力 → ハイパス → 低い音を切る → こもりを削る → 明瞭さ → 歯擦音を抑える → ノイズゲート → コンプレッサー → 持ち上げ → 出力
入力 → (フィルター前の音) ──────────────────────────────────────────────→ 出力
```

| 段 | ノード | していること | 「くっきり」の値 |
|---|---|---|---|
| ハイパス | BiquadFilter (highpass, Q 0.707 = バターワース) | 声より低い揺れ (机・空調・吹かれ) を切る | 80 Hz |
| 低い音を切る | BiquadFilter (highpass) 2 段 + BiquadFilter (notch) | 「切る周波数」より下を 1 オクターブで 24 dB 切り (4 次のバターワース。2 段の Q は 0.5412 と 1.3066)、電源の周波数とその倍の音を、Q 30 の細いノッチで削る。ハイパスだけでは残る、低いうなりと電源のブーンを落とす | 100 Hz, 電源 50 Hz, 倍音 10 本 (50〜500 Hz) |
| こもりを削る | BiquadFilter (peaking) | 200〜400 Hz の箱鳴りを下げる | 300 Hz, −4 dB, Q 1.0 |
| 明瞭さ | BiquadFilter (peaking) | 2〜5 kHz を持ち上げ、子音をはっきりさせる | 3.5 kHz, +4 dB, Q 0.9 |
| 歯擦音を抑える | AudioWorklet | 6〜9 kHz の帯域 (band-pass) の大きさを見て、しきい値を超えた分 × (1 − 1/比) だけ、その帯域を下げる (最大の削りまで)。強い「シー」の瞬間だけ効く | 7 kHz, −32 dB, 4:1, 最大 10 dB |
| ノイズゲート | AudioWorklet | 入力の大きさ (ピーク) がしきい値を下回ると、「保つ」時間のあと「下げる量」まで下げる。声の無い間の息・部屋の音が小さくなる。閉じるのはしきい値の約 4 dB 下 (ばたつきを防ぐ) | −48 dB, −24 dB, 開く 3 ms, 保つ 120 ms, 閉じる 160 ms |
| コンプレッサー | DynamicsCompressor | しきい値より大きい所を比で抑え、大きさのむらを減らす | −22 dB, 3:1, アタック 8 ms, リリース 160 ms, ニー 6 dB |
| 持ち上げ | Gain | コンプレッサーで下がった分を戻す | +3 dB |

- 各段の左の印で、その段だけ切れます (切った段は素通しになります)。
- Web Audio の highpass の Q は dB で渡します (Chromium の getFrequencyResponse で、Q −3.01 のとき切る周波数で −3.01 dB になることを確かめました)。表の Q は線形の値で、コードでは 20 log10(Q) にして渡しています。
- 「低い音を切る」のノッチは細いので、倍音と倍音のあいだの声はほぼそのまま通ります (試験では 175 Hz・325 Hz で −0.6 dB より小さい削り、1 kHz・3 kHz で ±0.3 dB 以内)。西日本の電源 (60 Hz) のときは「電源の周波数」を 60 にします。
- 前に保存した設定 (ブラウザに覚えたもの・JSON) に「低い音を切る」が無いときは、「くっきり」の値 (入) で埋まります。
- プリセット: 「くっきり」(上の値)、「やわらか」(削りと持ち上げを小さく、コンプレッサーを 2:1 でゆっくり、ゲートを浅く)、「そのまま」(全部の段を切る。書き出しの大きさそろえと無音詰めだけ)。
- 「聞く音」のボタンで、フィルターの後 / 前 (素の声) を切り替えます。再生中でも切り替わります。
- 「▶ 選んだ録音をくり返す」で選んだ 1 本をくり返し流し、聞きながらつまみを回せます。録音の一覧の ▶ は 1 回だけ流します。
- 「マイクの音をその場で聞く」は、マイクの音にフィルターをかけてそのまま流します。スピーカーでは音が回り込むので、ヘッドホンで使ってください。
- 「後」のメーターの横に、いま歯擦音を何 dB 削っているかと、ゲートが開いているか (閉じていれば何 dB 下げているか) が出ます。
- 設定はブラウザに覚えます。「設定を JSON で書き出す」で `voice-filter.json` を保存し、「JSON を読む」で戻せます (欠けた項目は「くっきり」の値で埋めます)。

## 保存する WAV の作り方

選んだ 1 本 (★) を次の順で WAV にします (`dsp.js` の `processTake`。サーバーへの保存もダウンロードも同じ):

1. OfflineAudioContext (44.1 kHz・モノラル) で、上と同じノードの並びに通して描き出す。録音が 48 kHz などでも、ここで 44.1 kHz になります。
2. 頭と尾の無音を詰める: 10 ms ごとの大きさ (RMS) を見て、いちばん大きい所から 35 dB 以内 (かつ −60 dBFS より上) の所を声とし、最初と最後の声の前後に「前後に残す」秒 (既定 0.05 秒) を残して切る。
3. 大きさをそろえる: 文ごとに大きさを測り、「大きさ」(既定 −16 LUFS 相当) になるよう音量を一律に上げ下げする。
   - 測り方は ITU-R BS.1770 にならった簡易のものです: K 特性 (高い方を約 +4 dB 持ち上げる棚と、約 38 Hz のハイパス) をかけ、400 ms のブロックを 100 ms ずつずらして平均の二乗を取り、−70 LUFS の絶対ゲートと、そこから −10 LU の相対ゲートを通ったブロックの平均を −0.691 + 10 log10 で表す。0.4 秒より短い文は全体を 1 ブロックとして測る。
   - K 特性の係数は、libebur128 が 48 kHz 以外のサンプリング周波数で係数を作るときの形と定数を使っています。定数は覚えていた値で、libebur128 のソースとは照らし合わせていません (確かめていない)。代わりに、書き出した WAV を ffmpeg の ebur128 フィルター (ITU-R BS.1770) で測り、このページの値と 0.5 LU 以内で合うことを試験 (`promo/tests/test_recorder.py`) で見ています。偽のマイクで書き出した 1 本 (N06_3) では、このページが −21.81、ffmpeg が −21.8 LUFS でした。
   - 上げた結果、ピーク (サンプルの値) が「ピーク上限」(既定 −1 dBFS) を超えるときは、上限で止めます。その文は目標より小さくなり、画面に「ピークで止めた」と出ます。サンプルの間の真のピークは見ていないので、ffmpeg で測ると上限より少し (0.1〜0.2 dB) 高く出ることがあります。
   - 動画にするときは `bgm.py mix` が声を −16 LUFS に合わせ直すので、ここでそろえるのは、文ごとの大きさの差をなくすためです。
4. 16 bit・44.1 kHz・モノラルの WAV にして、`<カット>_<文の番号>.wav` (`N07_2.wav` など、`voice.py` の `sentence_files` と同じ名前) で保存する。

画面の下に、保存した長さと、そろえる前と後の大きさ、残りの文の数が出ます。

## 動画に使う

`serve.py` で録ったときは、保存先 (`作業フォルダ/voice/recorded/`) に WAV と `voice.json` がもうそろっています。全部の文がそろったら (状態の 1 行が「36/36 文 保存済み」):

```
# 字幕と並べた声 (subs.ass・narration.wav・cues.json)
py promo/subs.py layout 作業フォルダ/voice/recorded/ 作業フォルダ/subs_recorded/ --script 作業フォルダ/script/narration.tsv

# BGM と混ぜる・動画に焼く (読み上げソフトの声のときと同じ。promo/README.md の手順)
```

サーバー無しで書き出したときは、先に `voice.json` を作ります:

```
py promo/voice.py adopt 作業フォルダ/script/narration.tsv 書き出したフォルダ/
```

`voice.json` (サーバーの保存でも `adopt` でも同じ) は、原稿の文の名前 (`N00_1.wav` …) と合う WAV の長さを測り、file・seconds・cut・start・end・ja・en、カットごとの収まり (声・枠・余り)、足りない文 (`missing`) を書きます。`adopt` をコマンドで打つと、枠を超えるカットに `OVER`、原稿に無い WAV に `not in the script:`、44.1 kHz・1 ch・16 bit でない WAV にその形を出し、足りない文があると終了コード 1 になります。`subs.py layout --script` は文がそろっていないと止まるので、全部録ってから使います。

## 試験

```
.venv/Scripts/python.exe -m unittest promo.tests.test_recorder promo.tests.test_voice   # サーバーと adopt (標準ライブラリだけ)
py -m unittest promo.tests.test_recorder                                                # ブラウザも (playwright があるとき)
```

- サーバー (`ServeApi`): 一時の作業フォルダで `serve.py` を別のスレッドに立て、HTTP で叩きます。状態・原稿・合成の声が出ること、PUT で WAV と `voice.json` ができること、フォルダの外 (`../`・`..%2F`・`\`) と原稿に無い名前と WAV でない中身が断られて何も書かれないこと、ほかの Host・Origin が断られること、使われているポートでは次のポートに立つこと、原稿が無いときの返事。
- ブラウザ (`RecorderInBrowser`、file:// で開く): Chromium を偽のマイク (`--use-fake-ui-for-media-stream --use-fake-device-for-media-stream`、Chromium が鳴らすビープ音) で開き、原稿を読み、1 文録って書き出した WAV が 44.1 kHz・16 bit・モノラルであること、大きさが −16 LUFS 相当 (またはピークで止めた) であること、フィルターの後と前で波形が変わること、ダウンロードの名前、キーでの移動、ffmpeg の ebur128 との差、手で選ぶ釦が出ていること。
- ブラウザ (`ServedPageInBrowser`、serve.py から開く): 原稿と合成の声がひとりでに出ること、手で選ぶ釦が隠れること、1 文録ると保存先に WAV と `voice.json` ができ、状態の 1 行と一覧の「保存 ✓」が変わること。
- playwright が無ければブラウザの試験は skip します。

## 気をつけること

- file:// で開いたとき、Chromium は Blob の URL からの AudioWorklet のモジュールを読まないので、`dsp.js` は読めなかったときに data: の URL で読み直します。
- 録音は、マイクの信号を AudioWorklet で取り出して PCM のまま持っています (MediaRecorder の圧縮した音は使っていません)。長い間録り続けると、そのぶんメモリを使います (1 分で約 11 MB)。
- 原稿の文を書き換えたあとに、前の文で録った録音を開くと「原稿の文が変わっています」と出ます。録り直してください。
- 合成の声のフォルダは読むだけで、書き換えません。保存先は合成の声と別のフォルダ (`voice/recorded/`) です。
