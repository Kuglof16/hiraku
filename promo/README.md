# promo — 動画のための画面と書き出し

動画だけに出る画面 (アプリの外) と、画面をコマごとに書き出して声・字幕・背景の音楽を付ける道具です。
声の原稿、合成した声、書き出したコマや動画は、リポジトリの外の作業フォルダに置きます。

- 1920×1080 の配置で作り、長さはすべて `--u` (= min(100vw/1920, 100vh/1080)) の倍数で書いています。1920×1080 の窓でも、3840×2160 の窓でも同じ配置になります
- 下の 170 px は字幕の帯なので、何も置きません (`?guides=1` で帯が見えます)
- 絵はすべて CSS と SVG で、このリポジトリの中で描いたものです。外の画像・素材は使っていません
- N05 の動画では、アプリの描画を下に敷き、この画面を `?layer=fg` (地を透明にする) で重ねます。`?layer=fg` で消えるのはタイルの仮の絵 (`.bg-only`) だけで、扉・扉の奥の光・車両・題字は描きます (下に敷くアプリの絵では車両を描かない)
- N05 の車両の絵は 1 か所で替わります: URL の `?hero=<PNG のパス>` (読み込みのときに 1 回だけ見て、時刻には関わりません)、無ければ `layout.json` の `n05.hero.src`、どちらも空なら `vehicle.js` の線画 (仮の絵) です。PNG は車両だけを透明の地で描いたもので、`n05.hero` の箱に縦横比を保って収めます (contain)。線画は線の下に暗い縁 (`halo`) を敷き、扉の線が車両の線の手前に来ないようにしています
- N05 の扉と観音開き: 画面いっぱいの 2 枚の扉板 (各 960×1080、外側の端が蝶番、鏡板 `n05.door.panel` と取っ手 `handle`) が車両の後ろにあります。重なりは奥から、扉の奥の光 → 扉 → 合わせ目の光とあふれる光 → 車両 → タイル → 閃光 → 題字です。`n05.times.door_open_s` (0.55 秒) までは閉じたままで、合わせ目の光 (`seam_w_px`・`seam_glow_w_px`) が強まり、車両は `hero_motion.push_scale` までゆっくり寄ります (ため)。そこから扉は `crack_dur_s` かけて `crack_deg` だけ割れ (`crack_ease`)、`hold_dur_s` 止まり、`open_dur_s` かけて `angle_deg` まで手前へ回ります (CSS の 3D、`perspective_px`、`rotateY`、緩急 `ease` で始めはゆっくり、画面の外へ抜けるところで速く)。回りきる時刻は `burst_s` と同じで、そこで扉は消え (`visibility`)、`?layer=fg` の地は透明に戻ります。大きく開き始めた時刻から、車両は割れずに `hero_fade_scale` まで少し寄りながら `hero_fade_dur_s` かけて消え、扉の奥の光と手前へあふれる光は `spill_dur_s` で消えます。2 回目までの形 (扉が 0.3 秒で開き始める、車両そのものが割れる) から、`burst_s`・`tiles_s`・`name_s`・`tag_s` を 0.3 秒ずつ遅らせました
- N05 の凝った開き方 (4 回目の形)。時刻と値はすべて `layout.json` の `n05` で、ページには書いていません
  - 錠と重さ: `times.latch_s` (0.38 秒) に閂 (`door.bolt`) が `latch_dur_s` かけて引け、扉が `latch_deg` だけ揺れ、合わせ目の光が一度ちらつきます。割れるときは `crack_deg` より `crack_overshoot_deg` だけ行き過ぎ、`settle_dur_s` (ためのうち) で戻ります。扉の自由端には厚み (`thickness_px`) があり、回ると光を受けた木口が見えます。鏡板は合わせ目の側が明るく、反対が暗い段の陰影です。大きく開くときの行き過ぎは描いていません (60° ほどで扉は画面の外に出るため)
  - 奥行き: `door_open_s` から `burst_s` まで、扉全体が `dolly_px` だけ手前へ来て (`perspective_px` の下の translateZ)、扉の前後の光も同じ倍率 (`perspective_px / (perspective_px − dolly_px)`、ページの中で計算) で大きくなります。床と影は描いていません (扉が画面いっぱいで床が見えず、画面の下は字幕の帯のため)
  - 光: 隙間から `fly_from` を中心に光の筋 (`rays`、本数・幅・角度は種 `seed` の疑似乱数) が割れ目の細さから広がり、それぞれの周期でゆらぎます。光の中にちり (`dust`、同じく種つき) が漂います。開ききる `burst_s` に光があふれ (`bloom`、`peak_alpha` 0.3 で白飛びさせない)、筋・ちり・あふれは 2.0 秒までに消えます
  - 車両: `times.mesh_in_s` から、車両の箱を覆う三角の網目 (`hero_mesh`、一辺 `size_px`、節点を種つきでずらす) が浮かびます。線は車両の絵の不透明な所にだけ出ます (SVG のフィルタで PNG のアルファと重ねる)。`mesh_out_s` から、要素が `fly_from` に近い順 (`reach_px` まで、少しの種つきのずれ) に光って縮み、絵のその部分を連れて消えます。最後の要素は大きく開き始めてから `hero_fade_dur_s` のうちに消えます。PNG が無いとき (線画) は前と同じく薄くなって消えます
  - タイル: 残像 (`tile_fx.ghosts` 本、`ghost_lag_s` ずつ遅れる輪郭) と着地の光 (イージング `ease.tile` が初めて着地点に届く時刻をページで計算)。アプリのタイル (`web/js/compose.js` の `flyIn`) と同じマス・開始時刻・動き・イージングなので、`?layer=fg` にも出します
  - 題字: `name_s` から、マスクの縁が文字の左端から右端まで (`name_wipe`、文字の幅は描いたあとに測る) 光の帯と一緒に走り、通った文字が光ってから夜の色に戻ります。副題は前と同じく静かに出ます
  - 確かめたこと: `?layer=fg` は開く前 (0〜0.4 秒) は全面不透明、割れているあいだは隙間の光の分だけ半透明 (96〜98 % が不透明)、1.8 秒からは題字の帯とタイルのまわりの光のほかは透明です
- N05 のタイルは、試験ごとの線画のループ (1 周 1.6〜2.4 秒) です。段差越え・傾斜台・横風・オフロード走行・DLC (上から見た絵)・急ブレーキ・長時間・発進・衝突・音振・疲労・熱の、試験のやり方だけを見せ、数字・目盛り・合否は出しません。色は黒インクと応力の色 (`--s1`〜`--s5`) だけです。ループはタイルが着地してから始まり (`--t0`)、すべて CSS のアニメーションなので時刻で止まります
- 字体は Windows に入っている Bahnschrift (英字と数字) と Noto Sans JP (日本語) を使い、無ければ順に代わりの字体になります

### N00 の 3D のペット

- ペットは `pets/pet3d.js` (v7、パッケージ役は 6 本組木) の 10 体で、並びは pet3d の `ROLES` の順 (まとめ役・設計役・パッケージ役、少し間をあけて 操安・動力・空力・衝突・強度信頼性・音振・熱)。three.js は `pets/viewer.html` と同じく jsDelivr の r170 を importmap で読み、`pet3d.js` はふつうの script で読んで THREE を渡します (ネットにつながっていないと描けません)
- 箱は 1 体 160×180 px、間隔 168 px (`n00.pets`)。WebGL の描き手はページの外に 1 つだけあり (箱 1 つの大きさ)、1 体ずつ描いてはその体の 2D の canvas に写します。カメラはどの体も同じ (`n00.camera`、視野 24°、方位 24°、仰角 12°、`viewer.html` と同じ合わせ方)。明かりは `viewer.html` の生成りの地の設定で、地は透明 (方眼が透けて見える)
- 動き: 分野のペットは札が灯るまで待機 (idle)、灯ると合格 (pass) の跳びを 1 回 (0.9 秒) してから報告 (report) の姿勢に。跳びが地面から始まるように、その体の時計をずらしています。まとめ役・設計役・パッケージ役は待機のままで、まばたきがそろわないよう時計を 1.3 秒ずつずらします (`n00.motion`)。姿は `timeline.js` の t からだけ決まり (`promo.onSeek` で `pet.update(t + ずれ, 状態, カメラ)`)、requestAnimationFrame の時刻・Date.now・乱数は使いません。同じ t を 2 回撮ると、ソフトの描画 (SwiftShader) でも `--gpu` でも画素が同じでした (2026-11-03)
- `promo.ready` は 3D のペットができるまで待つので、書き出しの最初のコマが空になりません
- 札: 分野の札 7 枚は 24 px (前は 27 px。強度信頼性の札 (幅約 178 px) が隣とぶつからないように)、3 体の名前の札は細い縁の 24 px。点検 (`story`) では札 10 (7 + 3)、動き 12 (ペット 10 体 + 名前か灯る札) を上限にしました

### N05 の点群・N18 の結び・N01〜N04 のラベル (参考の動画の演出を借りたもの)

値と時刻はすべて `layout.json` (`n05.hero_points`・`n05.times`、`n18`、`labels`) にあり、動きはすべて CSS のアニメーションです (種つきの疑似乱数で配置を決め、時刻で止まる)。

- **N05 の点群** (0〜0.46 秒): 点は網目 (`hero_mesh`) の節点のうち車両の上にあるものと、車両の輪郭の点です。どこが車両かは、車両の PNG の不透明度から 10 px のマスごとに計算した表 `n05.hero_points.mask` で決めます (`file://` で開いた PNG はページの中で画素を読めない (canvas が汚染される) ため、表にして持つ。表は試験の `hero_mask()` が PNG から計算し直して照合する)。点は種 `seed` で決めた位置 (画面の中、字幕の帯の上) から 0〜0.08 秒ずれて 0.22 秒で寄り、0.30 秒で集まりきると車両の絵が 0.16 秒でフェードインし、点は 0.36 秒から消えて網目の線 (0.2 秒から) に引き継ぎます。扉・閂・割れ・ため・開く・弾ける・タイル・題字の時刻は変えていません。`?layer=fg` でも出ます。線画 (PNG なし) のときは点を出しません
- **N18 の結び**: 0〜0.4 秒に 150 個の光の粒が中央の縦の線に吸い込まれ (遅く始まって速く)、線の場所に薄い光がたまります。縦の光は 0.4 秒から伸び (前は 0.15 秒から 0.6 秒かけて)、0.8 秒に帯へ開きます (`open_s` は変えず、`bgm.py` の粒の時刻もそのまま)。題字は 1 字ずつ上がるときに暖かい光のにじみ (text-shadow) をまとい、後ろの淡い光と一緒に 1.6 秒で落ち着きます。URL は 30 px 上げて (y 826)、その下 (y 872) に「HIRAKU Powered by Claude」を 20 px、生成りの文字 (`--on-night`) の不透明度 0.62 で 4.2 秒から出します。Claude のロゴや Anthropic の色は使っていません。Agent SDK の概要のページの Branding guidelines (https://code.claude.com/docs/en/agent-sdk/overview、2026-11-03 に読んだ) が許す言い方として挙げるのは "Claude Agent"・"Claude" (Agents の見出しの下)・"{YourAgentName} Powered by Claude" で、その 3 つ目の形にしています (前は「Built with Claude」。この言い方はそのページの許す側にも禁止の側にも挙がっていない)。URL の後ろに "· Powered by Claude" を足す `?powered=1` は、同じ言葉が 2 度出るので外しました
- **N01〜N04 のラベル**: `labels.html?cut=n01` のように URL でカットを選びます。`export.py` と `layout_check.py` はファイルのパスしか受け取れない (`?` が `%3F` になる) ので、同じページを `labels_n01.html`〜`labels_n04.html` の入口からも開けます (中身はどれも `labels.js`)。カットの長さは `n01`〜`n04` の `duration_s`。カットの頭から 0.2 秒で左から現れ (0.35 秒)、終わりの 0.3 秒前に消えきります。左下 (x 112・y 822・高さ 46、下端 868) で、アプリのカットの表示やタイルの左下の角の内側 (それらは y 886 で終わる) に収まり、字幕の帯にはかかりません。細い線 + 等幅の番号 (20 px) + 縦の細い線 + 言葉 (24 px) を、生成りの紙の札 (不透明度 0.9、黒インクの細い縁) に載せます。`?layer=fg` が無いときは紙の地を敷いて下見できます

ラベルの言葉 (声に合わせた案。いまは 1 番目の案を使う):

| カット | 声 (原稿 draft 6) | 案 1 (使用中) | 案 2 | 案 3 |
|---|---|---|---|---|
| N01 | 段差を越えられるか。 | 01 段差を越える | 01 段差越え | 01 段差 100 / 250 mm |
| N02 | でこぼこ道でも、傾いても、風を受けても、急にハンドルを切っても、倒れないか。 | 02 倒れない | 02 転倒 | 02 傾き・風・悪路・急ハンドル |
| N03 | 長く走っても、オーバーヒートしないか、どこまで速く走れるか。 | 03 長く・速く | 03 熱と速さ | 03 長時間・加速 |
| N04 | 衝突も、振動も、組み立ての順番も。 | 04 衝突・振動・組み立て | 04 全分野と組み立て | 04 衝突・振動・組み立ての順番 |

組み立て (`assemble.py`) では、`assembly.json` の N01〜N04 の `overlay` で、`<作業>/frames/labels_n01` などのコマを各カットの頭から重ねます。コマは次で作ります。

```
py promo/export.py frames promo/screens/labels_n01.html <作業>/frames/labels_n01 --fps 30 --layer fg --scale 1
```

### N08 のふつうの CAE のツール

- 実在の製品に似せないために作った架空のソフトです。製品名・ロゴは無く、窓の題は「無題 — 構造解析」だけです。値段と数 (警告の件数など) は出しません。値段の欄は「お見積もりはお問い合わせください」、警告は「要素の形が悪い箇所があります」「解が収束しませんでした」「拘束が足りません」の文言だけです。設定の窓の入力欄は、選ぶ欄は言葉 (「自動」「四面体・二次」など)、数を入れる欄は空のままです
- 窓の位置・大きさ・重なる順 (`n08.win.*.z`)・開く時刻 (`n08.times`)、全体の傾きと寄り (`n08.camera`)、手引き書の山 (`n08.books`、ずれと傾きは種つき)、最後の暗さ (`n08.dim`) は `layout.json` の `n08` にあります。時刻は声の区切り (無音の位置から測った値) に合わせています: ライセンスの窓 1.0 秒・追加モジュール 1.6 秒 (10 行が 2.74 秒まで)・矢印が 2.55 秒に「疲労」を押すと 2.75 秒に「ライセンスが見つかりません」、設定の窓 3.6〜4.4 秒 (0.2 秒ごと)、矢印が 4.85 秒に「計算を始める」を押し、警告 4.95・5.25・5.55 秒と手引き書 4.9〜5.3 秒、5.9 秒から暗くなる。矢印の道筋は `n08.pointer.path`
- 文字は HIRAKU の画面より小さく、いちばん小さい文字は 19 px です。画面は初めに 0.96 倍で描くので、そのときも 18 px 以上です
- 3D の表示の L 字の金具の網目は `n08.view` の種で節点をずらしたもので、警告が出る時刻に入り隅の要素が黄と赤に変わります

### N08b の数字の出典

### N10 の数の出どころ

値は `n10.html` の `DATA` にまとめ、差 (%) と ✓ はページの中で計算します (手で書いた差はありません)。

- ツールなしの Claude の答え: 広報部の N10 の記録 (答えの全文 `answer_*.json`・`tilt_answer_*.json`・`stress_answer_*.json`、リポジトリの外)。Claude Opus 5.5 を Claude Code の `claude -p` でツールなし (`--tools ""`) にして、1 つの問いを 3 回ずつ、2026-11-03 に聞いた。段差 100 mm の前輪 1 輪の水平の力は 3 回とも約 1,090 N、傾斜台で上の輪が浮く角度は約 39°・38°・39°。段差でのフレームの最大応力は、数字を出したのが 3 回のうち 1 回 (約 61 MPa) で、ほかの 2 回は数字を出さなかった。画面にもそのとおり書く
- HIRAKU の値: 動画用の運転 20261103-041110-offroad-4w-scripted の版 1 (同じ記録に写したもの)。手計算 1,092.9 N・39.85°・40.0 MPa (単純はり) と 77.09 MPa (つなぎ目、安全側)、解析 1,103.7 N (K1)・38.27° (K2)・61.15 MPa (K1)
- 差 = (HIRAKU の解析 − Claude の答え) ÷ Claude の答え。Claude の答えを予測とみて、HIRAKU が予測と解析を照合するときと同じ式で出す。答えが 3 つ違うとき (傾斜台) は、いちばん離れた答えの差を出す。いまの値は +1.3 %・−1.9 %・+0.2 %
- ✓ は、すべての答えの差が、HIRAKU が同じ量の照合で許す幅 (`DATA.rows[].tol_pct`) に入るときに付く。幅は動画用の運転の照合の記録の tolerance_rel (前輪の水平の力 10 %・傾斜台の角度 10 %・最大応力 15 %。`data/catalog/tests.yaml` で HIRAKU が決めた幅) で、外の規格ではない
- もっともらしい外れの例は、この記録では取れなかったので、この画面には出さない

### N17b の数 (`n17b_data.py`)

N17b は「量と深さ」を見せます。声の 1 文目 (構想は 10 万行。) で量を、2 文目 (その道を、Claude Code が拓きました。) で 1 回の運転の深さを 4 枚の札で出します。数はすべてコードで数えたもので、手で書いた数はありません。量は git の main の記録から、深さは 1 つの運転の記録 (`runs/<run_id>/events.jsonl`) から数えます。`n17b_data.py` が両方を読み、`screens/n17b.data.js` (`window.N17B_DATA`、生成物、手で直さない) を書き、`n17b.html` はそれを `<script src>` で読みます。声の 10 万行は構想の数なので、画面には出しません。

```
py promo/n17b_data.py --run <運転のフォルダ>
```

運転のフォルダは引数で渡します (リポジトリにパスを書かない。`runs/` はコミットしない)。いまは動画用の全部緑の運転 `20261103-182809-offroad-4w-scripted` を数えています。**凍結の時点でこの 1 行を回し直せば、数が新しくなります** (そのあと N17b を書き出し直す)。画面の右下に、数えた日時 (`counted_at`、JST)・git の ref と最新のコミット・運転の ID が小さく出ます。

量 (git の main、`amount`):

- 書いたコード: main の追跡しているファイル (`git ls-tree -r main`、main を取り出したときの `git ls-files` と同じ一覧) の行数を拡張子で分けて足したもの (Python `.py`、JavaScript `.js` `.mjs`、HTML、CSS)。空行とコメントを含みます。初めの 2 行に生成したと書いたファイル (`layout.data.js` など) は除きます
- コミット: main から届くすべて (`git log main`、マージを含む)
- 日数: 最初のコミットの日から main の最新のコミットの日まで (JST の暦、両端を数える。11/2 と 11/3 なら 2 日目)
- 自動の試験: Python のファイルの `def test_` の行の数

深さ (運転の events.jsonl、`depth`。同じ ID で出し直された記録は、契約 (`docs/contract.md`) のとおり最後の event を 1 件と数える):

- 見る分野: 最後の `domains.picked` の `picks` の数。組み立ては `judgement.updated` に分野 `assembly` があるとき「+ 組み立て」
- 解析のツール: `tool.checked` を名前ごとに最後の 1 件にして、使える (`usable`) ものの数。答えの分かっている例の件数は、その道具の `checks` の数の合計 (どれも合格でなければ数えずに止まる)
- 手計算と解析の照合: `comparison.recorded` の `comparison_id` の数。食い違いは `status` が `mismatch` のもの。原因を特定したものは、その `cause_id` の `cause.recorded` が `resolved` のもの
- 直して、合格: いちばん新しい版の、分野 (と組み立て) ごとの最後の `judgement.updated` が `green` の数。版の数は `design.created` の数
- 作者の名前・メール・パスは読みも書きもしません

いまの値 (2026-11-03 19:32 に main 033ef52 と運転 20261103-182809-offroad-4w-scripted を数えた): コード 71,001 行 (Python 54,023・JavaScript 12,895・HTML 2,658・CSS 1,425)、コミット 524 (マージ 203 を含む)、2 日目、試験 1,162。見る分野 7 + 組み立て、解析のツール 17 本 (答えの分かっている例 295 件)、照合 73 回 (食い違い 8 件、8 件とも原因を特定)、設計を直した 2 版目で 8 / 8 が合格。手計算の予測は 83 件 (画面には出さない)。

時刻は声に合わせています (`layout.json` の `n17b.times`。声の位置は録った声の cues の N17b: 1 文目 0.30〜1.93 秒、2 文目 2.28〜5.01 秒)。0.3 秒から「書いたコード」が出て、0.35〜1.65 秒に行数が数え上がり、1.0 秒にコミット・日数・試験の行が出る。2.2 秒から量が少し暗くなり、2.35 秒に見出し「1 回の運転で」と 1 枚目の札、そこから 0.4 秒ずつ札が出て (2.75・3.15・3.55 秒)、どれも 0.9 秒で数え上がり、最後は 4.45 秒に止まる。4.5 秒に数えた日時が出て、4.9 秒から終わりまでは止まった絵です。数え上がりは、通る値を読み込みのときに計算しておき、1 行ずつ送る CSS のアニメーション (`steps()`) で出すので、どのコマも整数で、同じ t からは同じ絵が出ます。

試験は `promo/tests/test_n17b.py`: 一時的なリポジトリと小さな運転の記録を作って数え方を確かめ、リポジトリの `n17b.data.js` の量が、そこに書かれたコミットを数え直した値と同じかを見ます (深さを数え直すのは、環境変数 `N17B_RUN` に運転のフォルダを入れたときだけ)。配置と時刻、画面に出た数がデータと同じか (playwright のある Python のとき) も見ます。

### 時刻で止める入口

画面のすべての動きは、1 つの時刻 t (秒) で決まります (`screens/timeline.js`)。

| 使い方 | 中身 |
|---|---|
| `n18.html` | 実時間で再生して繰り返す (下見)。スペースで一時停止、←→ で 1/30 秒ずつ |
| `n18.html?t=5` | t = 5 s で止めて描く |
| `await window.promo.seek(t)` | t へ動かし、その絵が描かれてから返る |
| `window.promo.duration` | 画面の長さ (秒) |
| `?layer=fg` | 地を透明にする (ほかの映像に重ねる) |

CSS のアニメーションは Web Animations API で止めて `currentTime` を t に合わせるので、同じ t からは毎回同じ絵が出ます (書き出したコマと撮り直したコマが 1 画素も違わないことを確かめました)。

アプリの画面 (`web/`) も同じ形の口を持っています (`?t=`、`?video=1`、描き終えてから返る `window.hiraku.seek(t)`)。`export.py` はどちらの画面も同じに扱います。

### 配置の決まり (`screens/layout.json`)

画面の配置と時刻の数値は `screens/layout.json` の 1 か所にだけ書きます。各カットの HTML と CSS には座標も時刻 (`--t-*`) も書きません。画面部 (アプリの画面) も N05 などの組み立てでこのファイルを読みます。

| ファイル | 中身 |
|---|---|
| `screens/layout.json` | 決まりの元。最上位のキーは `stage` (1920×1080)、`subtitle_band` (字幕の帯 y 910・高さ 170)、`safe` (余白の内側 x 96・y 60・1728×850)、`min_text_px` (文字の最小 18 px、日本語・英数字とも)、`colors` (`night`・`ink`・`tile_bg`・`tile_border`)、カットごとの `n00`・`n05`・`n08b`・`n18` (要素の位置と大きさ、長さ `duration_s`、時刻 `times`)、`check` (点検する時刻と、点検で許すもの。理由つき)。単位は名前で示す: `x`・`y`・`w`・`h` は設計の px、ほかの長さは `_px`、秒は `_s`、角度 (度) は `_deg` |
| `layout_build.py` | `layout.json` から `screens/layout.data.js` (`window.PROMO_LAYOUT`) を書く。画面は `file://` で開くので JSON を読み込めず、スクリプトにして渡す |
| `screens/layout.data.js` | 生成物。手で直さない。`layout.json` と違うと試験が落ちる |
| `screens/layout.js` | 決まりから座標を計算する。`<script src="layout.js" data-cut="n05">` で、そのカットの値を CSS 変数にして入れる (長さ `n05.title.name.y` → `--title-name-y: calc(62 * var(--u))`、`n05.tile.label.size_px` → `--tile-label-size-px`、時刻 `n05.times.burst_s` → `--t-burst: 1.25s`、色 `colors.tile_bg` → `--tile-bg`、動きの値は倍率 `n05.hero_motion.push_scale` → `--hero-motion-push-scale: 1.04` (単位なし)・長さ `burst_dur_s` → `--hero-motion-burst-dur: 0.4s`・緩急 `n05.ease.tile` → `--ease-tile: cubic-bezier(0.2, 0.9, 0.3, 1.15)`・角度 `n05.door.angle_deg` → `--door-angle: 105deg`、名前が `ease` か `*_ease` の 4 つの数 `n05.door.crack_ease` → `--door-crack-ease: cubic-bezier(...)`)。`gridCells(n05.grid)` は格子の各マス (`x + 列 × (tile_w + gap_x)`、`y + 行 × (tile_h + gap_y)`) を返し、N05 の 12 枚のタイルは `n05.tests` の順にこれで置く |

```
py promo/layout_build.py
```

`layout.json` を直したら、この 1 行を回してから画面を開きます。書き換えの前後で 4 カットを 4 時刻ずつ撮って比べ、16 枚すべて 1 画素も違わないことを確かめました。いまの形 (最上位にカットを置き、時刻も持つ形) に替えたときも、N00・N05・N18 を 4 時刻ずつ撮って 12 枚すべて 1 画素も違わず、`bgm.py` の WAV も 1 サンプルも違わないことを確かめました。各カットの HTML の `data-duration` は `duration_s` と同じ値にします (試験で見ます)。

### 配置の点検 (`layout_check.py`)

画面を決まった時刻で開き、名前つきの要素 (`data-box="名前"`。名前は点で区切る: `n05.title.name`・`n05.tile.step`・`n05.tile.step.label`・`n08b.fig.left.num`・`n08b.bars.large.value`・`n18.url`) と、文字を持つ見える要素 (透明度 0.05 未満・`visibility: hidden`・大きさ 0・親に切られて見えないものは除く) の箱を集めて、次を一覧にします。

- `band`: 字幕の帯 (y ≥ 910) に入ったもの。帯の飾り (`?guides=1`) は `layout.json` の `band_exempt` で除く
- `outside`: 画面 (0〜1920 × 0〜1080) の外にはみ出したもの
- `escape`: 名前つきの要素が、いちばん近い名前つきの親の箱からはみ出したもの (N08b の棒の値が棒の欄から出る、など)。動きの途中だけ出るものは `allow_escape` で px まで許す (N08b の説明の字が下から 14 px 上がってくる)
- `overlap`: 名前つきの要素どうしの重なり。意図した重なりは `allow_overlap` で許す (N18 の光と車両)
- `overflow`: 文字のあふれ (scrollWidth > clientWidth + 1、高さも同じ)。`allow_overflow` で、字の大きさに対する割合まで許せる (行の高さが字体の高さより低く、箱の下に数 px 出るもの)
- `small`: 1080p で最小 (`min_text_px` = 18 px、日本語・英数字とも) を下回る文字。この値はこのリポジトリの決まりで、外の規格ではありません
- `busy`: 出しすぎ。その時刻に見えているものを数え、`layout.json` の `story` の上限を越えたもの (下の「出しすぎの点検」)

#### 出しすぎの点検 (`story`・`data-kind`・`busy`)

`layout.json` の `story` は、カットごとに伝えること 1 つ (`story.cuts.<カット>.message`、3 秒で分かること) と、同時に画面に出してよい数の上限を持ちます。上限は `story.defaults` (札 `label` 3・グラフ `graph` 1・カラーバー `legend` 1・強調する数字 `number` 1・動いているもの `moving` 3・本文の文字 `body_text_px` 24 px) で、違うカットだけ `story.cuts.<カット>.limits` に理由 `why` をつけて書きます。上限を上げる前に、画面の方を減らせないか (隠す・小さくする・まとめる) を先に考えます。

要素は自分が何かを `data-kind` で言います (空白で区切って 2 つ以上も書ける)。

| `data-kind` | 中身 | 数え方 |
|---|---|---|
| `label` | 札、✓ と ✕、窓の題 | 見えている数。同じ種類の見えている要素の中にあるものは、外側と合わせて 1 つ |
| `graph` | グラフ (N08b の棒、N17b の帯) | 同じ |
| `legend` | カラーバー | 同じ |
| `number` | 強調する数字 (N08b の 99 % と 16 %、N10 の差) | 同じ |
| `moving` | 自分で動いていると言うもの (スクリプトで動かす画面は、動いているあいだだけ付ける) | 下の「動いているもの」に入る |
| `note` | 注・出典・目盛り・数えた日時など、読まなくても伝わる小さな文字 | 数えない。本文の文字からも除く |
| ほかの言葉 (`effect` など) | まとまって動く飾り (N18 の 150 個の光の粒) | 上限は無い。中で動くものは 1 つにまとまる |

- 動いているもの (`moving`): その t で Web Animations の進みの途中にある (遅れ `delay` を過ぎ、`delay + activeDuration` の前) 見えている要素と、`data-kind="moving"` の見えている要素。部品は、自分か上にある `data-kind` か `data-box` のついたいちばん近い要素 (その「もの」) として数え、動いているものの中にある動いているものは外側に含めます。名前の 1 字ずつの動きは名前 1 つ、車両の線画の線は車両 1 つです
- 本文の文字 (`body_text_px`): `data-kind` か `data-box` のついた要素の中の、見えている文字のうち、`data-kind="note"` の中でないもので、いちばん小さい大きさ (1080p の px)。全体の最小 `min_text_px` (18 px) は注や出典を含むすべての文字に効いたままです
- カットの名前: 画面の URL の `?cut=n01`、なければ `<body data-cut="n01">`、なければファイルの名前 (`n10.html` → `n10`)。`story` に無いカット (`labels_n01` など、試しの画面) は数えません。アプリのカット (`web/cut.html?cut=n01&run=…`) は URL から読みます
- 見えているかは、ほかの点検と同じ決まり (透明度 0.05 未満・`visibility: hidden`・大きさ 0・親に切られて見えないもの・何も描かないものは除く) です
- `report.md` の 2 つ目の表に、時刻ごとの数 (`n10: label 3 graph 0 legend 0 number 3 moving 0 body 24px`) を出します。`result.json` の各時刻の `counts` も同じ数です。上限を越えると、種類 `busy`、要素に何が (`label`・`moving`・`body_text_px` など)、詳細に何個で上限がいくつか (`label 4 > 3 (n10): …`) と数えたものの名前が出て、絵では数えたものを囲む箱を赤く描きます

2026-11-03 に付けたときに減らしたもの: N00 は 7 体のエージェントが 0.06 秒ずつずれて上がっていたのを、1 列でいっしょに上がるようにした。N05 はタイルの線画のループを、題字が出そろって (副題が入りきり、名前の光が冷めて) から始めるようにした (それまでは 12 枚の線画と題字で 14 の動き)。N10 は解析のセルの「K1 の解析」を隠し、差を太字にし、手計算の値が 2 つの行の単位を 24 px にした。N17b は書いたコードの言語ごとの内訳の行を消し、コミットの点の群れに付いていた `data-kind="moving"` (止まったあとも動いていると数えられた) を外した。N18 は光の粒の群れを 1 つのもの (`effect`) にした。上限の上書きは足していません。

```
py promo/layout_check.py promo/screens/n05.html <出力>
py promo/layout_check.py all <出力>
py promo/layout_check.py "http://127.0.0.1:8781/?run=sample&video=1" <出力> --at 2 8 15
```

時刻は `layout.json` の `check.times` (アプリは `app`) から取り、`--at` で変えられます。出力のフォルダはリポジトリの外を渡します。結果の `result.json`、表の `report.md`、時刻ごとの絵 (長辺 1280 px、問題の箱を赤い枠で描く)、全部を並べた `sheet.jpg` を書きます。問題が 1 件でもあれば終了コードは 1 です。canvas (WebGL) に描かれた文字は見えません。canvas の中で動くものも見えないので、そういう画面は動いているあいだ `data-kind="moving"` を付けます。広報部の画面 (`all`) は、`busy` を含めて 0 件です。

## 書き出し (`export.py`)

ブラウザ (headless Chromium) を 1920×1080 の配置のまま 2 倍の解像度で開き、コマごとに PNG で撮って ffmpeg でつなぎます。

`playwright` は動画の書き出しにだけ要るので、HIRAKU 本体の `requirements.txt` には入れず `promo/requirements-video.txt` に書いています。HIRAKU の venv ではなく、PC の Python (Windows では `py`) に入れて、その Python で `export.py` を回します。ffmpeg は PATH に置くか、環境変数 `FFMPEG` にその場所を書きます。

```
py -m pip install -r promo/requirements-video.txt
py -m playwright install chromium
```

```
py promo/export.py stills promo/screens/n18.html <作業>/stills --at 0.5 3 8
py promo/export.py frames promo/screens/n18.html <作業>/frames/n18 --fps 30
py promo/export.py encode <作業>/frames/n18 <作業>/clips/n18_1080p.mp4 --height 1080
py promo/export.py encode <作業>/frames/n18 <作業>/clips/n18_2160p.mp4 --height 2160
```

3840×2160 の PNG のコマから、1080p (Lanczos で縮小) と 4K の H.264 (BT.709) を作ります。

`encode` と `clip` は `--encoder auto|nvenc|x264` で圧縮のしかたを選びます。既定の `auto` は、ffmpeg に h264_nvenc があって短い試しの圧縮が通れば GPU (NVENC)、だめなら libx264 (CPU) です。NVENC は `-cq` を `--crf` と同じ数にした VBR で、測った N18 とアプリの再生のコマでは、可逆の元に対する SSIM が x264 (crf 14・slow) の 0.99875・0.99902 に対して 0.99946・0.99946、CPU 時間は 17.1・14.3 秒が 5.2・6.6 秒でした (ファイルは 1.8〜6.4 倍大きい)。設定と測った値は [ASSEMBLE.md](ASSEMBLE.md) の「GPU で圧縮する・フィルタを軽くする」。

アプリの再生は、サーバー (`python -m hiraku.webserve`) を立ててから URL で渡します。`--gpu` を付けると WebGL をグラフィックカードで描きます (付けないとソフトウェア描画)。

```
py promo/export.py frames "http://127.0.0.1:8765/?run=sample&video=1" <作業>/frames/app --gpu
```

書き出す長さは、画面が持つ長さ (`window.promo.duration`、アプリでは `window.hiraku.player.duration`) です。アプリの再生は、ふつうは間合いを整えた時間の軸で進みます (event どうしの短い間を延ばし、長すぎる間は切る)。記録の時刻のまま撮りたいときは、URL に `&pace=0` を足します。見本の記録では、間合いを整えると 19.73 秒、`pace=0` では 9.00 秒でした。`frames` は、はじめに読んだ長さを表示します。

この PC で測った 4K の 1 コマの時間:

| 画面 | 時間 |
|---|---|
| N18 (CSS) | 0.39 s |
| N00・N08b (CSS) | 0.13〜0.16 s |
| アプリの見本の再生 (three.js、`--gpu`) | 0.22 s |
| 同じ (ソフトウェア描画) | 0.45〜0.57 s |

3 分 (5400 コマ) は、GPU ならおよそ 20〜35 分です。1 コマの PNG は約 1.2 MB です。

## 1 本につなぐ (`assemble.py`)

原稿の枠どおりにカットの映像を並べ、境目のつなぎ (切る・溶ける・光・粒) と暗い画面の粒と光のにじみを付けて 1 本にします。表は `assembly.json`、使い方は [ASSEMBLE.md](ASSEMBLE.md)。

圧縮は既定で GPU (NVENC、`--encoder auto`。使えなければ libx264) です。光と粒のつなぎの式はつなぎのコマだけで走らせます。いまの表 (本人の声、1080p) の組み立ては、前の 2317.9 秒 (ffmpeg の CPU 6122.3 秒) が 292.1 秒 (CPU 679.7 秒) になりました。前と後の同じコマの SSIM は、見た目の層の無いカットで 0.99853 以上、層のあるカットで 0.97052 以上です (層のあるカットが 0.98 を下回る理由は粒の圧縮で、ASSEMBLE.md に書きました)。

## 声と字幕 (`voice.py`, `subs.py`)

声はこの PC で動かす AivisSpeech Engine (VOICEVOX と同じ形の HTTP の口) で合成します。原稿はタブ区切りで、1 行が 1 文です。

```
カット<TAB>枠 (0:00-0:07)<TAB>日本語 (字幕に出す形)<TAB>英語
```

読み違える語は、読みの表 (`書いた形<TAB>読ませる形`) で直します。字幕は書いた形のまま出します。

```
py promo/voice.py speakers
py promo/voice.py reading <原稿> --speaker <ID> --readings <読みの表>
py promo/voice.py synth   <原稿> <作業>/voice --speaker <ID> --readings <読みの表>
py promo/subs.py layout <作業>/voice <作業>/subs/n00 --cuts N00 --hot "99 %"
py promo/subs.py burn <作業>/clips/n00_1080p.mp4 <作業>/subs/n00/subs.ass <作業>/clips/n00_final.mp4 --audio <作業>/subs/n00/narration.wav
```

- `synth` は文ごとの WAV と `voice.json` を書き、カットごとに声が枠に入るかを表で出します
- `synth --only N07_2.wav N08b_2.wav` は、名前を挙げた文だけ合成し直し、ほかの文は前の声をそのまま使います (同じ文でも合成のたびに長さが 0.03〜0.05 秒ほど変わるので、直していない文の長さを動かさないため)
- `layout` は各カットの文を枠の頭から並べ、字幕 (ASS) と声をつないだ WAV を書きます。1 行に入らない日本語の文は「、」で分け、分け目は声の間 (無音) に合わせます
- 前のカットの声が終わっていなければ、次のカットの声はそのあとまで待ちます (声は重ならない)。枠を超えたカットと、何秒超えたかを表示します
- 「、」で分けるときは、行の数をいちばん少なくし、そのなかで行の幅がいちばんそろう分け方を選びます
- `layout --script <原稿>` は、枠と文を原稿から取り、声は合成したものをそのまま使います (枠を変えるたびに合成し直さなくてよい)。合成したあとに文が変わった文は、合成し直すように表示します
- `burn` は下の 170 px に黒インクの帯を敷き、字幕を焼き込みます。日本語は 48 px の太字で y = 995、英語は 30 px で y = 1040 に固定 (どちらもいつも 1 行)。座標は 1920×1080 で書き、4K では libass が拡大します

声のモデル: 「阿井田 茂」(制作 古山キリヲ)、Aivis Common Model License (ACML) 1.0。ライセンスの本文はエンジンの `GET /aivm_models` の `manifest.license` で読めます (営利の利用も可、クレジットの表記は任意)。

## 背景の音楽 (`bgm.py`)

音はすべて `bgm.py` の中で numpy と scipy で合成しています。外の曲・音源・サンプルは使っていません。

拍やリズムの無い、持続音と粒の曲です。

- ドローン: D と A (D2・A2・D3) の持続音。声部ごとに長さの違う周期 (11.3・14.7・19.1 秒) で、音量がゆっくり膨らんで引きます
- 和音の色: 話の区切りごとに、ニ長調の 5 音音階 (D E F# A B) から 1〜3 音を薄く足し、区切りの前後 2 秒で次の色へ移ります
- 粒: 色の音とドローンの D・A を 2〜3 オクターブ上 (MIDI 84〜104) で短く鳴らし、時刻をばらばらに散らします。1 秒あたりの粒の数は、N00〜N04 が 0.7〜0.9、題字の N05 が 6、課題の N06〜N08b が 0.5、仕組みの N09〜N14 が 2.5、N15〜N17 が 4.5、N18 が 1.5 (区切りの前後 1 秒でなめらかに変わる)
- 画面の時刻に合わせる粒は、画面と同じ `screens/layout.json` の `times` を読みます: N00 で札が灯るたびに 1 粒ずつ上がる (`n00.times.light_s`・`step_s`)、N05 で車両が開く瞬間に粒がはじける (`n05.times.burst_s`)、N18 で光が開く瞬間に 5 粒 (`n18.times.open_s`)
- 残響は、減衰するノイズ (残響時間 4.5 秒) を畳み込みます。はじめの 4 秒で現れ、最後の 3 秒で消えます
- 乱数は 0.5 秒ごとの区間に (種, 区間の番号) で作る生成器を使うので、同じ種なら、どこから作っても同じ音になります (`render --start --end` で一部だけ作れ、全体から切り出したものと一致します)

```
python promo/bgm.py render <原稿> <作業>/bgm/bgm.wav
python promo/bgm.py mix <作業>/bgm/bgm.wav <作業>/subs/all/narration.wav <作業>/bgm/mix.wav
py promo/subs.py burn <映像> <作業>/subs/all/subs.ass <出力>.mp4 --audio <作業>/bgm/mix.wav
```

`mix` は、音楽をはじめから終わりまで声より 15 LU 下 (`--under-voice-lu`) の一定の大きさにします (声の下で下げない)。`--duck-db 9` のように 0 より大きくすると、声の切れ目で音楽をその分だけ上げる作りになります (下げ始めは声の 0.3 秒前、声が止んでも 0.6 秒は下げたまま)。足したものは全体で -16 LUFS (`--lufs`) にし、真のピークを -3 dBFS (`--true-peak`) に抑えます (先読みの短いリミッター)。大きさと真のピークは ffmpeg の ebur128 (ITU-R BS.1770) で測ります。numpy と scipy (HIRAKU の `requirements.txt` にあるもの) と ffmpeg で動きます。
