# HIRAKU はどう合否を出すか

HIRAKU の考え方は 1 つです: **何も考えないで CAE を回さない**。解析の前に手計算で答えの見当をつけ、ツールの答えと比べる。不一致なら、どちらが何を見落としたかを言葉にするまで先へ進まない。合否はモデルが決めるのではなく、ツールのコードが記録から作ります。

例は `showcase/` の運転の記録からとりました。主なものは次の 2 つです。

- N15: `20261105-150416-offroad-4w-scripted`。台本の運転で、Claude は呼びません。
- N13: `20261105-160725-offroad-4w`。Claude Code のプラグインから動かした運転です。v7 で全部のタイルが OK になって終わりました。

いくつかの例は、`showcase/` のもう 1 つの N13 の運転 `20261105-094333-offroad-4w` (決まりを足す前の運転。下では「N13 の前の運転 094333」と書きます) からとりました。

数値は記録の値を丸めたものです。`cmp-` や `ana-` の ID で記録の中を引けます。

## 1. 流れ: 予測 → 解析 → 比べる → 判定

1. **予測** (`record_prediction`): 手計算の式 (K0) で、判定に使う量を解析の前に出します。
2. **解析** (`analyze`): 梁・板・車の動きなどのツールで同じ量を出します。どのツールも、答えの分かっている例と照合してから使います。
3. **比べる** (`compare`): 差が許す幅に入っていれば「予想通り」、外れれば「不一致」です。許す幅は荷重条件ごとに決まっていて、モデルは変えられません。
4. **判定** (`verdict`): 基準 (例: 5 mm 以下) と比べて、OK か NG かを出します。

## 2. 判定の根拠は 3 つ、それと「判定なし」

| 根拠 (`basis`) | いつ | 判定に使う値 |
|---|---|---|
| 予想通り (`match`) | 予測とツールが許す幅の中で合った | ツールの値 |
| 安全側 (`explained_safe_side`) | 不一致だが原因が説明でき、手計算の方が不利な側に出ている | 手計算の値 (不利な方) |
| 道を確かめてツールの値 (`path_checked`) | 手計算では値まで届かないが、力の通り道がつながっていることは手計算で確かめた | ツールの値 |
| 判定なし (`ends_case`) | 原因は説明できたが、手計算で確かめられるものが何も無い | なし。タイルは OK にならない |

**予想通り** (N15 v3、S4-brake35、停止距離)

- 最初の式は 8.03 m、ツールは 10.73 m で、34 % の不一致でした (許す幅 5 %)。
- 原因として「ブレーキで全輪がロックして滑ると、摩擦はタイヤの頂点の μ 0.6 より小さい約 0.44 になる」と書きました。
- 滑りを入れた式は 10.88 m で、ツールとの差 1.4 % の予想通りでした。基準 14 m 以下なので OK です (`cmp-0090`)。

**安全側** (N15 v3、R8-stress、部材の使用率)

- 手計算 0.90 に対し、ツールは 0.47 でした。
- 手計算は、応力を角で全部重ね、ねじれを固い横の部材で受けるとみるので、大きめに出ます。
- ツールは向きを確かめます (基準が「以下」なら、予測 ≥ 解析であること)。そのうえで、不利な方の 0.90 で判定しました。基準 1.0 以下で OK です (`cmp-0078`)。向きが逆なら断ります。

**道を確かめてツールの値** (N15 v3〜v5、R7-hand-300N、ハンドルを 300 N で押したときの握りの動き)

- 板の入った枠は手では解けないので、手計算は上から押さえる値しか出せません。v3 で 9.66 mm、ツールは 0.815 mm でした。
- 上限が OK だったとしても、それはゆるすぎて何も言っていません。
- 代わりに、手計算で「部品から部材まで、力の道がつながっている (つながらない部品 0)」と予測しました。ツールの解析も、支えの無い荷重を 0 と出しています。
- その条件で、ツールの値 0.815 mm と基準 5 mm を比べて OK にしました (`cmp-0082`)。v5 では 9.10 mm と 0.538 mm です。
- 道がつながっていなければ、ツールは `tool_decides` を断ります。
- この道の判定は、NG にもなります。N13 v6 の R1-step100 では、シェルのツールがつなぎ目の壁の応力を 151.4 MPa と出し (手計算 114.9 MPa、差 31.8 %)、基準 143.3 MPa を超えて NG でした (`cmp-0127`)。設計役がレールの肉厚を上げた v7 で、75.1 MPa の OK です (`cmp-0152`)。

**判定なし** (N13 の前の運転 094333 の v2〜v4、R7-hand-300N)

- この運転は、上の決まりができる前の運転です。手計算 9.78 mm、ツール 1.05 mm の不一致を `ends_case` で記録し、R7-hand は最後まで判定なしでした。
- 「手計算は値に届かなくても、考えた跡 (力の道) はある」ことを判定に使えるようにしたのが、上の `path_checked` です。N13 の 160725 では、同じ R7-hand が全部の v で `path_checked` の OK です (v7 で 0.727 mm、`cmp-0137`)。
- いまの `ends_case` は、道の確かめもできないときだけに使います。

ほかに、NG になる根拠が 2 つあります。

- 力の通り道が無いとき (`unsupported_load`): N13 v2 の R8-push-725N (乗員を横から押す) では、両側の乗員の腰と肩の 4 点を受ける物がありませんでした。ツールはそれを数え、そのまま NG になりました (`ana-0019`)。v3 で横の棒が付き、13.4 mm で、基準 25 mm 以下の OK になりました (`cmp-0045`)。
- 手計算が予測していない場所でツールが基準を超えたとき (`hot_spot`): ツールはモデルの全体を見て、利用率の高い順に場所を並べます (`hot_spots`)。手計算が見ていない場所が基準を超えると、その荷重条件は NG になります。CAE は、手計算が見ようと思っていなかった所を見つけるのも役目だからです。この決まりは、上の 2 つの運転のあとで足したので、その記録にはまだ例がありません。

## 3. 分野のタイルが OK になる決まり (a)〜(d)

その v の、その分野のどの荷重条件についても、次の 4 つがそろったときだけ OK です。

- **(a) OK の判定がある。** 場所や量の違う判定がいくつかあるときは、どれも OK であること。
  - N15 は v5 で、N13 は v7 で全部のタイルが OK になり、運転は `done` で終わりました。
- **(b) いちばん新しく比べた結果が、予想通りか、説明の付いた不一致 (安全側か、道を確かめたもの) である。**
  - 前の不一致は、あとで比べた結果で置き換わります。
  - 上の S4-brake35 では、8.03 m の不一致のあと 10.88 m の予想通りが来たので、止まりません。
- **(c) 判定に使う量で、基準を超えた解析が無い。**
  - N15 v4 の R1s-step100 は、シェルのツールがレールの継ぎ目で 554 MPa を出しました (基準 143 MPa)。強度は NG です。
  - v5 でレールの壁と補強を足し、130 MPa で OK になりました。
- **(d) 前の v で重いツールが基準超えを出したなら、この v でも同じか重いツールで確かめ直してある。** (例は、N13 の前の運転 094333)
  - v3 では、シェルのツールが 643 MPa を出しました。手計算 590 MPa と比べて予想通りで、NG です (`cmp-0051`)。
  - v4 では、梁の解析 (`ana-0048`) が、v4 のシェルのメッシュを作れずに失敗しました。そのあと、軽い梁のモデル (段差越えのツール) が 67.8 MPa を出して手計算と比べて予想通りで、R1-step100 は OK の判定になりました (`cmp-0062`)。シェルのツールの解析 (`ana-0056`) が失敗したのは、この OK のあとです。重いツールで確かめ直さないままの OK です。
  - 軽いツールの OK では、重いツールが出した基準超えは消えません。これを見て (d) を足しました。N13 の 160725 では、v7 の R1-step100 を梁 (61.9 MPa、`cmp-0147`) とシェル (75.1 MPa、`cmp-0152`) の両方で確かめています。

## 4. hooks (HK1〜HK6) が止めるもの

hooks は Claude Code の PreToolUse で動き、決まりに外れた呼び出しを、その場で断ります。断るときは、何をすれば進めるかを返します。

| | 止めるもの | 記録の例 |
|---|---|---|
| HK1 | 予測の無い解析 | N15 v1: パッケージ役の最初の `analyze` を止めました。重なる部品を数える予測を記録してから回っています。台本がわざと 1 回、予測の前に呼んでいます (`data/catalog/scripted.yaml` の `show_hk1`)。`showcase/` の Claude の運転の記録には、HK1 で止めた例はありません |
| HK2 | 照合 (答えの分かっている例) に通っていないツール | N13: Claude が運転の中で横転の保護枠のツール `rops_pushover` を書きました。答えの分かっている例 3 つ (片持ち梁の先の振れ 4.172 mm、足元を固めた門形の枠が横に崩れる力 3231.9 N と、上から押して崩れる力 6463.8 N) を同じ値で出すことを確かめてから使っています |
| HK3 | 原因の書かれていない不一致があるのに先へ進むこと | N15 v3〜v5: 段差 P1-step100 で、前輪の力が手計算 1209 N、ツール 1045 N (−13.5 %、許す幅 10 %) でした。次に比べるのを止め、原因を書いてから進めています (3 回)。N13 v6 でも、上の 151.4 MPa の不一致で 1 回止めています |
| HK4 | 判定の付いていない分野を残したまま終わること | N13 の前の運転 094333: まとめ役の終わりを 1 回断り、上限で終わりました。R7-hand は判定なしと記録に残っています |
| HK5 | 軽い計算で NG が残るうちの重い計算 | N13 v2: 段 1 の R8-push-725N が NG のまま、段 3 のシェルで R1-step100 を回そうとしたのを止めました。先に設計を直しています。v3 でも、段 1 の R4-rops がまだ判定の無いうちに止めています |
| HK6 | モジュールの持ち場を越えた変更 | N13 の前の運転 094333: パッケージ役が、乗員まわりのモジュールの変数 `rollbar_width` を変えようとした v の組み立てを断りました |

まとめると、HIRAKU が OK と言えるのは次のどちらかのときだけです。

- 手計算とツールを比べて予想通りだったとき。
- 不一致の理由を言葉にし、その理由が判定の向きを甘くしないことを確かめたとき。
