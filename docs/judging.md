# HIRAKU はどう合否を出すか

HIRAKU の考え方は 1 つです: **何も考えないで CAE を回さない**。解析の前に手計算で答えの見当をつけ、ツールの答えと照らし合わせる。合わなければ、どちらが何を見落としたかを言葉にするまで先へ進まない。合否はモデルが決めるのではなく、ツールのコードが記録から作ります。

例はすべて `showcase/` の 2 つの運転の記録からとりました。

- N15: `20261105-150416-offroad-4w-scripted`。台本の運転で、Claude は呼びません。
- N13: `20261105-094333-offroad-4w`。Claude Code のプラグインから動かした運転です。

数値は記録の値を丸めたものです。`cmp-` や `ana-` の ID で記録の中を引けます。

## 1. 流れ: 予測 → ツール → 照合 → 合否

1. **予測** (`record_prediction`): 手計算の式 (K0) で、判定に使う量を解析の前に出します。
2. **ツール** (`analyze`): 梁・板・車の動きなどのツールで同じ量を出します。どのツールも、答えの分かっている例と照合してから使います。
3. **照合** (`compare`): 差が許す幅に入っていれば「一致」、外れれば「食い違い」です。許す幅は荷重条件ごとに決まっていて、モデルは変えられません。
4. **合否** (`verdict`): 基準 (例: 5 mm 以下) と比べて、合格か赤かを出します。

## 2. 合否の根拠は 3 つ、それと「判定なし」

| 根拠 (`basis`) | いつ | 合否に使う値 |
|---|---|---|
| 一致 (`match`) | 予測とツールが許す幅の中で合った | ツールの値 |
| 安全側 (`explained_safe_side`) | 食い違ったが原因が説明でき、手計算の方が不利な側に出ている | 手計算の値 (不利な方) |
| 道を確かめてツールの値 (`path_checked`) | 手計算では値まで届かないが、力の通り道がつながっていることは手計算で確かめた | ツールの値 |
| 判定なし (`ends_case`) | 原因は説明できたが、手計算で確かめられるものが何も無い | なし。タイルは緑にならない |

**一致** (N15 版 3、S4-brake35、停止距離)

- 最初の式は 8.03 m、ツールは 10.73 m で、34 % 食い違いました (許す幅 5 %)。
- 原因として「ブレーキで全輪がロックして滑ると、摩擦はタイヤの頂点の μ 0.6 より小さい約 0.44 になる」と書きました。
- 滑りを入れた式は 10.88 m で、ツールと 1.4 % で一致しました。基準 14 m 以下なので合格です (`cmp-0090`)。

**安全側** (N15 版 3、R8-stress、部材の使用率)

- 手計算 0.90 に対し、ツールは 0.47 でした。
- 手計算は、応力を角で全部重ね、ねじれを固い横の部材で受けるとみるので、大きめに出ます。
- ツールは向きを確かめます (基準が「以下」なら、予測 ≥ 解析であること)。そのうえで、不利な方の 0.90 で合否を出しました。基準 1.0 以下で合格です (`cmp-0078`)。向きが逆なら断ります。

**道を確かめてツールの値** (N15 版 3〜5、R7-hand-300N、ハンドルを 300 N で押したときの握りの動き)

- 板の入った枠は手では解けないので、手計算は上から押さえる値しか出せません。版 3 で 9.66 mm、ツールは 0.815 mm でした。
- 上限が合格したとしても、それはゆるすぎて何も言っていません。
- 代わりに、手計算で「部品から部材まで、力の道がつながっている (つながらない部品 0)」と予測しました。ツールの解析も、支えの無い荷重を 0 と出しています。
- その条件で、ツールの値 0.815 mm と基準 5 mm を比べて合格にしました (`cmp-0082`)。版 5 では 9.10 mm と 0.538 mm です。
- 道がつながっていなければ、ツールは `tool_decides` を断ります。

**判定なし** (N13 版 2〜4、同じ R7-hand-300N)

- この運転は、上の決まりができる前の運転です。手計算 9.78 mm、ツール 1.05 mm の食い違いを `ends_case` で記録し、R7-hand は最後まで判定なしでした。
- 運転は「判定の付いていない分野を残して」止まっています。
- 「手計算は値に届かなくても、考えた跡 (力の道) はある」ことを合否に使えるようにしたのが、上の `path_checked` です。
- いまの `ends_case` は、道の確かめもできないときだけに使います。

ほかに、合否が赤になる根拠がもう 1 つあります。力の通り道が無いとき (`unsupported_load`) です。

- N13 版 2 の R8-push-725N (乗員を横から押す) では、両側の乗員の腰と肩、4 点を受ける物がありませんでした。
- ツールはそれを数え、そのまま赤になりました (`ana-0021`)。
- 版 3 で横の棒が付き、14.1 mm で、基準 25 mm 以下に合格しました。

## 3. 分野のタイルが緑になる決まり (a)〜(d)

その版の、その分野のどの荷重条件についても、次の 4 つがそろったときだけ緑です。

- **(a) 合格の合否がある。**
  - N15 版 5 で全部のタイルが緑になり、運転は `done` で終わりました。
- **(b) いちばん新しい照合が、一致か、説明の付いた食い違い (安全側か、道を確かめたもの) である。**
  - 前の食い違いは、あとの照合で置き換わります。
  - 上の S4-brake35 では、8.03 m の食い違いのあと 10.88 m の一致が来たので、止まりません。
- **(c) 判定に使う量で、基準を超えた解析が無い。**
  - N15 版 4 の R1s-step100 は、シェルのツールがレールの継ぎ目で 554 MPa を出しました (基準 143 MPa)。強度は赤です。
  - 版 5 でレールの壁と補強を足し、130 MPa で合格しました。
- **(d) 前の版で重いツールが基準超えを出したなら、この版でも同じか重いツールで確かめ直してある。**
  - N13 版 3 では、シェルのツールが 643 MPa を出しました。手計算 590 MPa と一致していて、赤です (`cmp-0051`)。
  - 版 4 では、シェルのメッシュが作れずに解析が失敗しました (`ana-0048`)。そのあと、軽い梁のモデル (段差越えのツール) が 67.8 MPa を出して手計算と一致し、R1-step100 は合格の判定になりました (`cmp-0062`)。重いツールで確かめ直さないままの合格です。
  - 軽いツールの合格では、重いツールが出した基準超えは消えません。これを見て (d) を足しました。この運転の強度のタイルは、R7-hand が判定なしで残ったため、どの版でも緑にはなっていません。

## 4. hooks (HK1〜HK6) が止めるもの

hooks は Claude Code の PreToolUse で動き、決まりに外れた呼び出しを、その場で断ります。断るときは、何をすれば進めるかを返します。

| | 止めるもの | 記録の例 |
|---|---|---|
| HK1 | 予測の無い解析 | N15 版 1: パッケージ役の最初の `analyze` を止めました。重なる部品を数える予測を記録してから回っています |
| HK2 | 照合 (答えの分かっている例) に通っていないツール | N13: Claude が運転の中で横転の保護枠のツール `rops_pushover_frame` を書きました。足元を固めた門形の枠の崩れる力 4243.7 N (塑性の式) を同じ値で出すことを確かめてから使っています |
| HK3 | 原因の書かれていない食い違いがあるのに先へ進むこと | N15 版 3〜5: 段差 P1-step100 で、前輪の力が手計算 1209 N、ツール 1045 N (−13.5 %、許す幅 10 %) でした。次の照合を止め、原因を書いてから進めています (3 回) |
| HK4 | 判定の付いていない分野を残したまま終わること | N13: まとめ役の終わりを 1 回断り、上限で終わりました。R7-hand は判定なしと記録に残っています |
| HK5 | 軽い計算で赤が残るうちの重い計算 | N13 版 2: 段 1 の R8-push-725N が赤のまま、段 3 のシェルで R1-step100 を回そうとしたのを止めました。先に設計を直しています |
| HK6 | モジュールの持ち場を越えた変更 | N13: パッケージ役が、乗員まわりのモジュールの変数 `rollbar_width` を変えようとした版の組み立てを断りました |

まとめると、HIRAKU が「合格」と言えるのは次のどちらかのときだけです。

- 手計算とツールが合ったとき。
- 合わない理由を言葉にし、その理由が合否の向きを甘くしないことを確かめたとき。
