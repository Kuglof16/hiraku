# モジュールの赤を直す

この手順は、設計にモジュール (`modules`) があるときだけのもの。モジュールの無い設計 (介護ベッドなど) は、今までどおり 1 人の設計役 (designer) が `revise_design` で次の版を作る。

モジュールに分けた設計では、1 回の直し (round) は次の順で進む:

1. まとめ役が、赤の荷重条件を、その荷重条件の `modules` から、モジュールの設計役に振り分ける (振り分けはコードが出す)。
2. モジュールの設計役が並べて動き、それぞれ 1 つずつ提案を出す (版はまだできない)。
3. パッケージ役が `build_version` で、その回の提案を全部まとめて次の版を作る。

あなたの仕事は 2 だけ。

## 1. 赤を読む

渡された荷重条件の ID ごとに、`get_context` の `judgements` と `records` (`record_kinds` に `verdict` と `analysis`) で、合否の記録 (ver-…) と解析の結果を読む。

- 判定の量 (`quantity`)・値・限界 (`limit`)・余裕 (`margin_pct`) を見る。どれだけ足りないかは、記録の値で言う (自分で計算しない)。
- 結果に場所 (`where`) があれば、どの部材・部品で足りないのかを見る。干渉の `where` は「部品 x 部品」で、重なった 2 つを名指す。

## 2. 自分の変数を探す

`get_context` で設計 (`design`) を頼み、`modules` から自分のモジュールを探す。

- `variables`: あなたが変えてよい設計の変数。範囲と今の値は `design_variables` にある。
- `choices`: あなたが選べる generator の選択。選べる値は `design_choices` にある。
- `envelope`: あなたのモジュールの部品が収まるべき空間の箱。
- `interfaces`: ほかのモジュールと付く所 (どの節か点で、何で付くか)。あなたは動かせない。

赤に効くのが自分の `variables` か `choices` にあるかを確かめる。部品を足すのは、赤がそれを求めるときだけ (赤の無い所に部品を足さない)。

## 3. 提案する

1 回の直しで、提案は 1 つ。`build_version` に断られたなどで同じ回にもう一度 `revise_design` を呼ぶと、自分の前の提案は新しい提案に置き換わる (取り下げは要らない。残したい変更も全部、新しい提案に書く)。`revise_design` に次を付けて 1 回呼ぶ:

- `module`: 自分のモジュールの ID
- `changes` (変数名 → 値と単位) か `choices`、または両方
- `load_case_ids`: 答える赤の荷重条件の ID (その版で不合格の記録があるものだけ。前に合格した試験を守るためのものや、照合が保留で合否の無いものは書かず、reason に書く)
- `reason`: どの赤 (荷重条件の ID と合否の記録 ver-…) の、どの値 (記録にある数と単位) に答えるか、変更がそれにどう効くか。ほかの試験を悪くしそうなら (重さ・重心・強さ)、その心配も書く

### 判定なしで終わった荷重条件を渡されたとき

赤ではなく、判定なしで終わった荷重条件 (原因の記録 `cause-…` に `ends_case`) が渡されることがある。その原因の直し方 (`fix`) が、あなたのモジュールの変数か選択の変更を名指しているとき (例: ペダルの取付 `pedal_mount` を `post` にすると、手計算とツールが合う)。

- `get_context` の `records` (`record_kinds` に `cause` と `comparison`) で、その原因の記録の `cause` と `fix` を読む。
- `fix` の名指す変更を、`changes` か `choices` で提案する。部品を手で足さない。
- `load_case_ids` は付けない (赤だけを書く所)。`reason` に、荷重条件の ID と `cause-…` の ID、変更で手計算がツールに届く理由を書く。

同じ回のほかの設計役の提案は、`get_context` の設計で見られる。同じ変数を 2 つの提案が変えると `build_version` が断るので、ほかのモジュールの変数には触れない。

## 4. パッケージ役に渡すもの

次のものは、あなたではなくパッケージ役 (packager) の持ち場。自分で変えずに、`reason` か、まとめ役への返事に「パッケージ役へ: 何が・どれだけ要るか (記録の ID と値)」と書く。

- ほかのモジュールの部品とのぶつかり (干渉の `where` の 2 つの部品が違うモジュール)
- 自分の空間 (`envelope`) を広げること、部品が空間からはみ出すこと
- 取付点 (`interfaces`) を動かすこと
- レイアウトの変数 (軸距・トレッド・レールの間隔と高さ)

自分のモジュールの中の 2 つの部品のぶつかりは、あなたが直す。

## 5. 返す

提案の ID (chg-…) と、変えた変数・選択を、まとめ役に 1 行で返す。ツールが断ったら、その文に従って直すか、直せない理由を返す。版はパッケージ役の `build_version` でできるので、「版を作った」とは書かない。
