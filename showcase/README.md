# showcase: 再生のために残した実行

画面が何も計算せずに再生する実行のフォルダです。リポジトリのフォルダで、`requirements.txt` を入れた Python から `python -m hiraku.webserve` を起こし、`http://127.0.0.1:8765/` を開きます (部品の入っていない Python では、ツールの棚が出ません)。

開くと一覧「HIRAKU でできること」が出ます。「まずはこれ」の「見る」は、ここのいちばん新しい実行 (実行の名前の順。今は下の 5) を再生します (`--default-run <実行の名前>` で変えられます)。ほかの実行は、一覧の「記録を見る」か `?run=<実行の名前>` で開きます。下の見出しは、一覧に出る行の題です。

実行は 7 つで、6 つは Claude Code のプラグインで Claude が回したもの (`project.json` の `driver` が `claude_code_plugin`)、1 つ (下の 1) は台本の運転 (`driver` が `scripted`) です。

フォルダには、画面が読むものだけを入れました: `events.jsonl`、`project.json`、`report.json`、Claude がツールを書いた実行では `tools/`。記録のフォルダ `v00N/` は入れていません (どの記録も event の中にあります)。解析ごとの時間の値は、1 つの量につき 160 点までに間引きました。両端と山は残します (`prepare.py`)。結果・予測・比べた結果・判定は記録のままです。フォルダは `python showcase/prepare.py runs/<実行の名前>` で作ります。1〜3 は、`prepare.py` が `,` と `:` のあとの空白を書かなくなる前に作ったので、空白が残っています (値は同じ)。

見る順のおすすめ: 1、4、5、6、2、3、7。

## 1. 「決まった手順で最後まで・v5 で全部 OK」 `20261105-150416-offroad-4w-scripted`

動画の N15 の要件 (`data/requirements/offroad-4w-n15.yaml`、23 の試験) を、デモの車で、台本の運転で回したものです (Claude を呼ばない、費用 0)。車はモジュールに分かれていて、直すたびにモジュールの設計役が提案し、パッケージ役が次の v を組みます。HK5 が軽い段から確かめさせるので、どの v も、最初に NG が出た段で止まります。

| v | NG | 次の v で変えたこと |
|---|---|---|
| v1 | 組み立て: H1-motion、H1-steer、H3-body-size、H3-knee-angle、H6-spray、H7-handhold | レイアウト、乗り込むときの手すり |
| v2 | 組み立て: H7-opening | 横のネットを、開く留め具で止める |
| v3 | 動力: P3-accel40 | モーター 17 kW |
| v4 | 強度: R1s-step100 (レールの継ぎ目のシェルのホットスポット) | レールの壁、ガセット、横の部材 |
| v5 | なし: 終わり | |

R7-hand (ハンドルの握りの動き) は、力の道を手計算で確かめた (`path_checked`) うえで、ツールの値で判定しています。手計算は上から押さえる値で、v3 と v4 で 9.66 mm に対し 0.815 mm、v5 で 9.10 mm に対し 0.538 mm です (基準 5 mm)。hooks が止めたのは、HK1 が 1 回 (台本がわざと予測の前に `analyze` を 1 回呼ぶ。`data/catalog/scripted.yaml` の `show_hk1`) と HK3 が 3 回です。

## 4. 「Claude の運転で最後まで・v7 で全部 OK」 `20261105-160725-offroad-4w`

Claude Code のプラグインで回した、最後の N13 の実行です。依頼は 2 と同じ (横転のときの守り R4 を求め、棚に R4 のツールは無い) で、決まりは 1 と同じ (`path_checked`、OK の決まり (d))。6 回直して、v7 で全部のタイルが OK になって終わりました。

| v | NG |
|---|---|
| v1 | 組み立て: H1-motion、H1-steer、H3-body-size、H3-knee-angle |
| v2 | 強度: R8-push-725N (乗員の 4 点に、押される相手が無い。`unsupported_load`) |
| v3〜v5 | 強度: R4-rops、乗員の空間に届いた (隙間 −3.55、−3.33、−2.94 mm) |
| v6 | 強度: R1-step100、シェルのツールのホットスポット 151.4 MPa (基準 143.3 MPa) |
| v7 | なし: 終わり |

強度の役 (cae.strength) が、実行の中で R4 のツールを書き、確かめてから使いました (`tools/rops_pushover-1.py`)。v7 で R4-rops は隙間 77.3 mm で OK です。v7 の R1-step100 は、梁のツール (61.9 MPa、予想通り) とシェルのツール (75.1 MPa、`path_checked`) の両方で OK、R7-hand は 0.727 mm で OK (`path_checked`) です。hooks が止めた呼び出しは、HK5 が 2 回 (v2 で軽い段の試験が NG のまま、v3 でまだ判定の無いうちに、シェルのツールを回そうとした) と HK3 が 1 回 (v6: 手計算 114.9 MPa とシェルの 151.4 MPa が不一致のまま、原因を書く前) です。ほかに、強度の役の終わりを HK4 が 2 回断っています (`hook.blocked_stop`)。

この実行のあと、R4 の荷重条件は、傾斜台で倒した車がロールバーで地面に着く計算 (R4-rollover、土と舗装の 2 通り) に変わりました。この記録の R4-rops は、そのときのコードの荷重条件です。

## 5. 「Claude の運転・v5 まで・NG が残った」 `20261107-164004-free-utv`

Claude Code のプラグインで、依頼の文から始めた実行です。依頼は、林道を走る 2 人乗りの小さな電動の 4 輪車 (最高 40 km/h、500 kg まで、積載 150 kg、横転しても乗員を守る) です。まとめ役 (Claude) が依頼の性質を答え、コードがそこから 7 分野 (操安・動力・空力・衝突・強度信頼性・音振・熱) と試験を選び、まとめ役がそれを `add_tests` で見直しました。足した試験は無く、その理由を書いています (`domains.picked` の `no_addition_reason`、seq 17)。

設計役は型 `ladder_4w` から v1 を作り、v5 まで直しました。解析は 107 回 (`analysis.finished`)。v5 では 7 分野のどれにも判定があり、操安・動力・空力・音振・熱は OK、衝突と強度信頼性は NG です。

- 衝突 (C1): 乗員の空間の余裕 −545.7 mm (基準 ≥ 0 mm) と、骨組みの割れた割合 0.1726 (基準 ≤ 0.03)
- 強度信頼性 (R9、サスペンションの取付): 金具の板の曲げの利用率 2.69 と、溶接の利用率 1.127 (基準はどちらも ≤ 1)。この分野には、判定の無い試験が 6 つ残っています (R4-rollover と R4-rollover-pavement を含む)

Claude は実行の中でツールを 3 つ書き、確かめてから棚に入れました (`tools/rops_frame_push-1.py`、`tools/rops_frame_push2-1.py`、`tools/drag_force_steady-1.py` と、それぞれの確かめ)。記録の最後は「Claude Code のセッションが閉じたので、実行を止めました」(`stop_code` は `user_stop`) です。セッションが閉じたのは、Claude Code の使用の上限に着いたためです (理由は記録にはありません)。プラグインの実行なので、費用は記録にありません。
